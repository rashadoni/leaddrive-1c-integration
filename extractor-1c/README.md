# Извлечение карты метаданных 1С 8.2 (для 1С-программистов клиента)

**Зачем:** таблицы 1С в SQL называются `_Document12345`, поля — `_Fld6789`. Чтобы ETL и
аналитика понимали, что есть что, нужна карта «объект конфигурации ↔ таблица/поле СУБД».

**Где запускать:** на **рабочей базе** (обработка читает ТОЛЬКО метаданные, ни одной
строки данных не читает, выполняется секунды). Можно и на копии, если она подключена
к серверу 1С.

## Шаги (5–10 минут)

1. Конфигуратор → `Файл → Новый → Внешняя обработка`.
2. Добавьте обычную форму (основную). На форму — одну кнопку «Выполнить».
3. Откройте модуль формы и вставьте целиком код из
   [`metadata-extractor-module.bsl`](metadata-extractor-module.bsl).
   Обработчик кнопки должен называться `КнопкаВыполнитьНажатие` (по умолчанию так и будет).
4. Сохраните как `МетаданныеВыгрузка.epf`, откройте в режиме Предприятие, нажмите кнопку,
   укажите путь — получите `metadata-dump.txt` (UTF-8, TSV-подобный формат).
5. Передайте файл нам.

## Что делает обработка

- **Часть 1 (если платформа поддерживает):** вызывает
  `ПолучитьСтруктуруХраненияБазыДанных(, Истина)` → точная карта
  «объект → таблица СУБД → поле СУБД». На некоторых сборках 8.2 метод может
  отсутствовать — обработка это переживёт (строка `#STORAGE_STRUCTURE|UNAVAILABLE`),
  ничего не падает.
- **Часть 2 (всегда):** выгружает дерево метаданных — документы, справочники, регистры
  накопления/сведений/бухгалтерии, перечисления: имена, синонимы, реквизиты, табличные
  части, измерения/ресурсы.

Если Часть 1 недоступна, карту достроим со своей стороны:
`etl/src/decode-dbnames.ts` декодирует служебную запись `DBNames` из таблицы `Params`
SQL-базы (uuid → номер таблицы), плюс эвристика по структуре колонок
(`discovery-sql/03`, `04`). Т.е. **любой исход шага 1 нас устраивает** — главное получить
Часть 2.

## Безопасность

- Обработка не пишет в базу, не читает данные документов, не требует монопольного режима.
- Выгружаются только ИМЕНА объектов и реквизитов (структура), не данные.
